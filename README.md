# Stereo Selector

用于快速查看双目 RGB、深度图、伪彩图和 PLY 点云的数据工作台。它把常用的图片、深度、双目和点云检查集中在一个窗口中；人工筛选是可选工作流，不再是默认主流程。界面参考 Codex 桌面版与 VS Code，面向熟悉数据处理的开发人员。

## 当前功能

- 提供“查看模式”和“筛选模式”。查看模式默认启用，只显示工作区与单行播放器；筛选模式才显示接受、拒绝、待定、缺陷备注和输出设置。模式按项目记忆。
- 左侧为默认折叠的 40 px 活动栏，按需打开“数据、显示、分析、筛选”；右侧检查器按需显示，中央空间优先用于图片和点云。
- 顶部仅保留模式、打开项目、布局和设置；检查工具使用图标按钮和悬停提示。
- `Tab` 隐藏或恢复全部界面工具，`F11` 全屏，`Ctrl+Shift+P` 打开可搜索的命令面板；双击视图标题可聚焦或退出聚焦。
- 选择项目文件夹后，递归识别 `left`、`right`、`depth_fsd`、`depth_color`、`ply` 目录（也支持常见别名）。
- 非标准目录会结合文件夹/文件名、扩展名和图像位深自主推断类别；项目不要求同时具备五种数据。
- 按相对路径和去除模态前后缀后的文件名匹配样本；支持场景子目录。
- 支持 `ColorLeft`、`ColorRight`、`DepthColor` 等驼峰式相机文件名。
- 文件名带采集序号但左右相机时间戳略有差异时，自动按采集序号配对，并保留场景目录防止跨场景混合。
- 左侧可勾选任意数量的模态并同步展示。
- 允许选择 0、1 或多种视图：未选择时显示空状态，单视图会占满工作区。
- 底部提供样本时间轴、上一帧/播放暂停/下一帧控制和 `0.5–10 fps` 速度选择，可连续播放当前选中的图片与点云视图。
- 支持将项目文件夹直接拖放到窗口打开。
- 启动时立即显示轻量启动页；进入主界面后保持空状态，不再自动弹出文件夹选择框。
- 支持常见 RGB、8/16 位灰度/深度图片；滚轮缩放、拖动平移、双击还原。
- 右侧检查器提供 RGB/灰度/深度直方图，以及最小值、最大值、均值、标准差、有效像素比例和文件信息。
- 支持亮度、对比度、Gamma、曝光、深度手动范围/自动百分位拉伸，以及灰度、Turbo、Viridis LUT。
- 可高亮深度 0、65535、非有限值和范围外像素；支持 1:1、适应窗口、适应宽度、矩形 ROI 统计、线段像素/标定长度测量和当前视图导出。
- 内嵌 PLY 点云预览，支持彩色/无色、ASCII/二进制 PLY；左键旋转、右键平移、滚轮缩放。
- 图片与点云在后台线程加载；快速资源直接平滑替换，超过延迟阈值才显示加载动画，并缓存最近浏览内容。
- 当前帧显示后会低优先级预取后两帧和前一帧；缓存按估算内存限制淘汰，不再只按文件数量保留。
- 图片解码、图像/深度统计和点云处理使用独立后台任务；播放期间跳过完整统计，停止后再异步补齐。
- 可开启同步十字光标；在 RGB、伪彩图或深度图上检查时均可联动显示 RGB、匹配的原始深度值，并在导入左目内参后计算相机坐标 XYZ。
- 可开启图片同步缩放和平移，也可查看左右图透明叠加和绝对差值；导入双目标定后可切换校正前/校正后图像，十字光标显示左右对应坐标与视差估计。
- 可将点云投影回左图；点击图片像素会在点云中高亮对应点，点选点云会在图片中显示对应位置。
- 深度质量面板独立加载当前匹配深度，显示有效范围、无效值、零值、空洞和包含 65535 饱和值的极大值比例。
- 支持导入 JSON、YAML 格式的左右目内参、畸变参数及双目外参；标定文件按项目记忆。
- 内置 `libra2000`、`libra3000` 两套标定；主页面可快速切换，新增自定义标定统一在“设置 → 标定”中管理。
- 可显示左右目极线；标定文件含基础矩阵或完整双目标定时使用精确极线，否则按已校正图像显示水平参考线。
- 点云使用左相机坐标系正视：原点为左相机光心，X 向图像右侧、Y 向图像下方、Z 向相机正前方；有左目内参时按 `u=fx·X/(Z+cam_offset)+cx`、`v=fy·Y/(Z+cam_offset)+cy` 精确投影。
- 点云支持 RGB、X/Y/Z、相机深度和高度着色，坐标轴/网格/相机视锥，前后左右/俯视标准视角，深浅背景切换。
- 点云支持点选 XYZ/RGB/相机距离、两点距离测量、屏幕矩形框选、X/Y/Z 范围裁剪，以及实时点大小调整；当前视角可直接导出。
- `←` / `→` 切换样本，空格播放/暂停。筛选模式中 `Enter` 接受、`X` 拒绝、`N` 跳到下一待定样本、`Shift+N` 跳到下一拒绝样本。
- `1`–`5` 切换对比视图，`F` 聚焦单视图，`Esc` 返回，`Ctrl+B` 隐藏/显示侧栏。
- 使用与工作区融合的深色标题栏，支持拖动、双击最大化以及最小化/最大化/还原/关闭。
- 提供统一的应用与任务栏图标，并使用 Windows 应用标识保持任务栏显示一致。
- 无边框窗口通过 Windows 原生命中测试支持四边、四角缩放与窗口吸附。
- 设置页支持黑色/白色主题、自定义按钮文字与快捷键、自动前进，以及点云显示上限、虚拟相机后移、采样网格、点半径、最远距离、飞点过滤强度和近点遮挡。
- 左侧栏和顶部检查工具栏使用统一方向按钮收起与展开，支持可反向的平滑动画；工作区采用克制的分隔线和统一圆角。
- 主页面、设置、映射、输出和审核弹窗采用统一的 Codex 风格卡片、圆角与状态层级；侧栏、设置分页、开关和图片切换带有轻量动画。
- 点云后端在启动页显示期间并行预热，点云视图持续复用，切换类别不会重建顶层窗口。
- 点云在后台完成坐标变换、默认 10 m 距离过滤、投影网格采样和飞点过滤；默认采样网格为 5 px、点半径为 1 px。开启遮挡时，同一网格保留最近点并按从远到近提交渲染。
- 输出位置和文件夹名称可按项目自定义；默认仍为项目同级的 `<项目名>_select`。
- 筛选模式支持接受、拒绝、待定三种状态。接受后，将该样本匹配到的所有文件复制到当前输出文件夹并保持原目录结构；单个文件完成后才会原子替换最终输出。
- 可为每组样本记录内置或自定义缺陷标签与文字备注，接受状态和审核信息保存在输出目录的 `stereo_selector_review.json`。
- 重新打开项目时，会校验输出文件大小并恢复已接受状态，不会把中断复制的半成品误判为已接受。
- 无法自动识别目录时，可手动指定五种视图文件夹；也可开启“按顺序强制匹配”，忽略文件名并按自然排序位置直接对应。
- 手动视图目录与强制匹配选项按项目分别保存，切换多个项目不会互相覆盖。

## 安装与运行（Windows）

需要 Python 3.10–3.13，推荐 Python 3.12。首次运行：

```powershell
.\setup.ps1
.\run.ps1
```

也可从命令行直接打开项目：

```powershell
.\run.ps1 D:\data\capture_project
```

## 可选：打包 EXE

```powershell
.\build_exe.ps1
```

日常源码更改无需执行打包。仅在需要发布版本时手动运行以上命令，v1.1 输出为 `dist\StereoSelector-v1.1.exe`。

发布构建可使用内置冒烟测试验证全部图片和点云渲染器：

```powershell
.\dist\StereoSelector-v1.1.exe --smoke-test D:\data\capture_project
```

退出码 `0` 表示全部可用，`2` 表示至少一种渲染器失败，`3` 表示加载超时。

## 匹配约定

最稳妥的命名是各目录使用相同文件名，例如 `000001.png` / `000001.ply`。程序也会匹配如下名称：

```text
left/left_rgb_000001.png
right/right_rgb_000001.png
depth_fsd/depth_000001.tiff
depth_color/depth_color_000001.png
ply/000001.ply
```

如有多个场景，可以保持镜像结构：

```text
project/
  scene_01/left/...
  scene_01/right/...
  scene_02/left/...
  scene_02/right/...
```

如果各视图的文件名完全不同，点击侧栏中的“配置视图与匹配”，选择对应文件夹并开启“按顺序强制匹配”。程序会将各目录自然排序后的第 1、2、3…个文件直接组成同一组；文件数量不同时，超出部分会作为缺少部分视图的样本保留。

## 标定文件

支持 JSON、YAML 和 OpenCV YAML。常用 JSON 结构如下：

```json
{
  "left": {
    "width": 1280,
    "height": 720,
    "camera_matrix": [[800, 0, 640], [0, 800, 360], [0, 0, 1]],
    "distortion": [-0.1, 0.01, 0, 0, 0]
  },
  "right": {
    "camera_matrix": [[800, 0, 640], [0, 800, 360], [0, 0, 1]],
    "distortion": [0, 0, 0, 0, 0]
  },
  "left_to_right": {
    "rotation": [[1, 0, 0], [0, 1, 0], [0, 0, 1]],
    "translation": [-0.12, 0, 0]
  },
  "cloud_to_left": {
    "rotation": [[1, 0, 0], [0, 1, 0], [0, 0, 1]],
    "translation": [0, 0, 0]
  }
}
```

也识别 OpenCV 常见的 `M1`、`D1`、`M2`、`D2`、`R`、`T`、`F` 字段。`cloud_to_left` 会在显示前把 PLY 从其原坐标系变换到左目相机坐标系；平移单位和深度值单位应保持一致。

## GitHub Actions 跨平台构建

`.github/workflows/build-desktop.yml` 会在主分支更新、面向主分支的 PR、版本标签以及手动运行时执行测试并构建桌面包。v1.1 生成以下文件：

| 平台 | 输出 |
| --- | --- |
| Windows x64 | `StereoSelector-v1.1.exe` |
| macOS Intel | `StereoSelector-v1.1-macOS-x64.dmg` |
| macOS Apple Silicon | `StereoSelector-v1.1-macOS-arm64.dmg` |
| Linux x64（Ubuntu 20.04 / glibc 2.31 及以上） | `StereoSelector-v1.1-linux-x86_64.AppImage` |

每次构建的文件会作为 Actions artifact 保留 30 天。推送与项目版本一致的 `v*` 标签时，工作流也会把四个平台包上传到已有 GitHub Release。若标签已经存在，可从 Actions 手动运行工作流并在 `release_tag` 中填写 `v1.1`。

macOS 包目前使用临时签名，没有 Apple Developer ID 公证；首次打开时可能需要在系统“隐私与安全性”中确认。Linux AppImage 仍依赖目标机器提供可用的图形桌面、OpenGL 驱动和基础系统图形库。

Linux 包在官方 `ubuntu:20.04` 容器中使用 Python 3.11 和受约束的 PySide6 6.7.3 构建，并在 glibc 2.31 环境中完成单元测试和最终 AppImage 冒烟测试。它适用于 x86_64 架构的 Ubuntu 20.04 及更新版本；不支持 ARM64 或基于 musl libc 的发行版。

## UI 开发约定

后续主界面、设置页、对话框和新控件均遵循 [UI 前端规范](docs/UI_FRONTEND_SPEC.md)。规范定义了深浅主题令牌、字体、间距、圆角、组件尺寸、交互状态、动画和变更验收清单；新增 UI 不应再创建独立的一套样式。
